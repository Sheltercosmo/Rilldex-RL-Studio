## Shared layers and domain boundaries

**Whole-corpus process-reference replay (12 October):** All 1,000 AgentProcessBench trajectories now pass source/reference alignment, including 250 BFCL records that previously failed on flat tool definitions. The BFCL v2 path preserves original function schemas and 278 unlinked tool results without inventing dispatches from inline markup. The other three collections retain adapter v1; 391 customer-side τ² calls remain external. All 8,509 quality judgments remain at whole-assistant-message grain, outside semantic activity inputs. Earlier HotpotQA/τ² exposure is accounted for in the final task-group allocation. [Audit, practical import limits and validation](../research/agentprocess-reference-2026-10-12/README.md). This is public replay and reference preparation, not live environment or diagnostic-accuracy validation.

**Semantic binding follow-through (11 October):** Public Harbor fixtures exposed a gap after successful import: feedback without a native call ID was linked by the source adapter but ignored by semantic candidate retrieval and map cards. New history workspaces can freeze `--feedback-linkage adapter-feedback-links/1` to use the shared, unambiguous adapter associations in both layers. Four public Harbor/mini-SWE-agent situations now reach and match the reviewed relation expectations. This is relation-only development evidence with supplied local fields, not automatic whole-trace accuracy. [Comparison, command and boundaries](../research/feedback-direct-sets-2026-10-11/README.md).

1. **Source capture:** immutable native record, exact pointers, actor/trajectory identity, observed call/result bindings, explicit clocks and outcomes. No behavior label is required to connect a producer.
2. **Deterministic measurements:** source counts, coverage, explicit rewards, episode steps/return/ending flags. The same graph/database/monitor and evidence infrastructure consumes every contract.
3. **Semantic observations:** activities, targets, plans, feedback assessment and selected relations. These require suitable context and a versioned observer. Importing numeric actions or a new domain does not validate an existing semantic harness.
4. **Diagnostic and strategy measures:** require the relevant lower-layer evidence, outcome definition and held-out review. Unknown remains unknown. A source-native repeated dispatch is not necessarily a loop: moving right twice in different states illustrates why interpretation needs context.

| Environment family | Useful capture boundary | Functions that can transfer | Additional domain evidence |
|---|---|---|---|
| Verifiable reasoning | Decoded prompt/completion and explicit score | Text volume, score distributions, source review and supplied-clock trends | Answer extraction/verifier contract, tokenizer, sampling and task difficulty; flat text has no reliable internal tool graph |
| Software / terminal | ATIF / SWE trajectory plus result sidecars | Action/response map, feedback inspection, existing reviewed software observers | Command/tool semantics, artifact/test identity, reward configuration, environment revision |
| Search / retrieval | Structured model conversation before flattening | Native query/result links and linked source inspection | Corpus/version, retrieved documents, citation boundaries; answer-seeking intent is a separate judgment |
| Browser / GUI | Transitions plus model-visible DOM/text and media references | Actions, visible response timeline and environment endings | Visual observer, screenshot/state coverage, target identity and accepted completion criteria |
| Business / tool workflows | Actor-aware tool conversation | Calls/results, schemas, state history and reviewed relation queries | User consent/policy/task rules, private simulator boundary, tool-specific outcome semantics |
| Controlled interactive / synthetic worlds | Reset and environment transitions | Step counts, return, termination/truncation and source-linked graphs | Action meanings, goal, observed state, episode boundaries; transfer to real workflows remains unproven |

The universal component is the evidence and measurement machinery. Environment semantics are supplied explicitly; a software-only purpose label is not imposed on browser, business or numeric-state actions. Base-unit accuracy and semantic generalization remain separate validation requirements.

The optional [state recorder](STATE_CAPTURE.md) adds source-bound object versions, check criteria, outcomes and delivery requirements across single-rollout adapters. Eight actual controlled software/business executions agree across SWE-agent, Harbor ATIF and portable chat encodings, with 24 automatically materialized live measurements. This validates the common contract, not native execution of those agent frameworks. Producers still supply correct scope and stability assertions; dependency discovery and semantic correctness are not inferred. See [runtime audit and boundaries](../research/state-capture-2026-10-11/README.md).

## Implemented source contracts

- `chat-messages/1`: `messages`, optional function `tools`, explicit `metadata` and `outcome`. Supports recorded developer/system/user/assistant/tool roles, null assistant content with calls, optional assistant reasoning, typed content parts, string or object arguments. Native IDs bind results even when parallel responses arrive in a different order. Missing IDs remain unlinked; duplicate IDs are rejected. Independent histories are not concatenated. Invalid generated argument strings remain evidence.
- `environment-episode/1`: optional `goal` and producer-declared `visible_context`, reset in `initial.observation`, and `steps` with action/observation/reward plus native `done` **or** `terminated`/`truncated`. `info` and evaluator fields stay in raw source. NumPy scalars convert without adding a NumPy SDK dependency. Project arrays deliberately; use media references for screenshots. A step after an explicit ending is rejected.
- `generation/1`: recorded string `prompt`, string `completion`, optional metadata/outcome. Does not parse alleged tool execution out of text or guess a tokenizer. Structured action measures are unavailable, rather than zero.
- `atif`: explicit alias for the existing native trajectory decoder. Auto-detection retains existing Harbor identity to avoid silently changing archived source hashes.
- `tau-bench/1`: exact native text simulation plus optional shared `info`, matching `task`, and collection provenance. Auto-detects native multi-simulation Results and bare SimulationRun. Bundles project only the relevant original task/config/simulation into each immutable source; preserve original collection hash and pointers. Native participant and pending call IDs govern links. Trial/seed are evaluation provenance, not training steps; raw private simulator/evaluator fields never enter agent packets. Audio/chunks/ticks are rejected explicitly.
  Normalization version `tau-bench/2` preserves standalone native user stop/transfer/out-of-scope markers as protocol controls, outside semantic-unit requests. Mixed natural text remains a user contribution. The input envelope remains `tau-bench/1`; old stored sources are not rewritten.

Portable envelopes use `trajectory_format` with the exact version above. `outcome.reward` is a finite explicitly chosen producer score; `outcome.success` is an explicit boolean or null. No scalar or ending is promoted into success. A step-return sum is not silently substituted for the training reward. Unselected reward components can remain in raw source.

`Episode` records one environment instance and episode. Vectorized environments must be demultiplexed with environment/episode identities; auto-reset wrappers must preserve the actual final observation before the next reset. The [SB3 adapter](STABLE_BASELINES.md) handles its native vector environments and autoresets. Other producers supply those boundaries explicitly; do not send the next episode's reset observation as the previous episode's transition.

Helpers are in [`tracker/portable.py`](../tracker/portable.py); transport is [`tracker/capture.py`](../tracker/capture.py). Python SDK requires 3.11+, with no trainer dependencies. Other languages or older Python processes can use the same HTTP envelope. Native log schemas and tool semantics should be version-pinned by the exporter.

## Connectivity and practical use

Open [Data connections](http://127.0.0.1:8765/connections) for the evidence matrix, directory setup, snapshot preflight and imports. [In-app setup recipes](http://127.0.0.1:8765/integration-guide) cover native trajectories, conversations, episodes, generation exports, raw HTTP and recovery.

```bash
python -m pip install .
python -m rilldex serve --port 8765
# No database, model or running server required:
python -m rilldex check snapshot.json
```

`GET /api/integrations` returns source formats and research-backed routes. `POST /api/integrations/check` accepts `document`, optional `format`, `metadata`, and `sources`; it returns source counts, linked/unlinked responses, exact available measurements, missing clocks and function prerequisites. It performs no persistence or inference. The one-off importer performs the same check before saving.

Browser uploads and the CLI now share a byte-preserving JSON/JSONL reader. JSONL requires an experiment name; duplicate completions on different physical lines stay separate. `POST /api/import-file/check` and `/api/import-file` accept `{file:{name,base64},format,metadata}`. All records validate before a single per-file transaction; one bad final record saves nothing from that file. Check responses count every record, with five optional detail previews. Browser files allow 14 MiB of decoded bytes; use `python -m rilldex import results.json` for larger files up to 100,000,000 bytes. For verl JSONL, supply `--metadata experiment.json`, containing at least `{"experiment":"your-run"}`. Reimporting unchanged bytes with identical metadata is idempotent. Separate files remain separate transactions.

Use a durable outbox per producer/worker. Bind to the actual agent or environment callback; do not patch the global model client. Start with all final rollout records, then add bounded intermediate snapshots when live inspection is needed. Preserve native files if the queue fills. A callback must handle capture failure explicitly, not swallow it or accidentally stop training without a deliberate policy.

Required identity conventions:

- Stable experiment and producer names across recovery; a fresh outbox needs a fresh producer namespace.
- Distinct rollout IDs for prompt repetitions, agents and episode resets; successive snapshots reuse the same ID and monotonically increasing revision.
- Explicit task/environment versions, train/eval split, sampling policy, reward definition and selection into training. `training_inclusion` separates filtered/admitted/pending populations when supplied; the tracker does not infer it.
- `training_step` is the chosen chart coordinate and `training_step_basis` names its meaning. `generation_step`, `learner_step` and `policy_version` remain separate. Unknowns stay absent. Do not relabel asynchronous rollout order as a verified model checkpoint.

The monitoring cohort separates source adapter, environment, split, reward definition, sampling, selected clock and training-inclusion metadata. This prevents known incompatible records being pooled; it cannot prove omitted metadata matches. No inverse-probability correction or statistically representative sampling claim is implemented.

## Functions now available for environment records

| Measure | Denominator / eligibility | What it does not establish |
|---|---|---|
| Recorded environment steps | Explicit transition count | Reasoning steps or semantic activities |
| Recorded episode return | Reset, explicit ending, all finite step rewards and finite sum | Trainer reward or task correctness |
| Environment termination reported | Final native Gymnasium flag | Positive vs negative terminal state |
| Environment truncation reported | Final native Gymnasium flag | Failure or the reason for truncation |
| Episode ending reported | Native done, or terminated OR truncated | Success |

Add these from **Monitor → Add monitor → Recorded source**. Per-rollout values and training curves retain coverage and point-to-source drilldowns. Investigation signals recognize them as source measures. Raw reward/flag pointers now resolve against the exact saved revision in the evidence panel. Metric schema extends to `rollout-behavior/16` without erasing prior measurements. In-progress and failed producer snapshots are inspectable but excluded from completed-rollout population values; lifecycle failure is not automatically task failure.

## Validation and gaps

The [feedback-retrieval audit](../research/feedback-retrieval-2026-10-11/README.md) extends semantic-side checks to distant results and middle-log evidence. Across 50 frozen development situations, a recent-plus-lexical pool improves complete target availability from 36/45 to 43/45 reference-bearing cases, but one previously correct selection regresses and input cost rises. All 1,185 Python tests and nine browser checks pass. Existing airline/retail extractions yield zero eligible feedback questions, which is an explicit annotation/harness coverage gap, not transfer evidence. The new policy is opt-in and the previous live observer remains unchanged.

The [concurrent native audit](../research/concurrent-training-2026-10-11/README.md) adds two independent CPU trainers with live capture/delivery, 328 completions, four separate experiment/split cohorts, fault injection and pushed browser updates. Every source reward and aggregate is checked. Optional worker reports expose queue state without claiming expected-training-sample coverage. Captured training preserves baseline tokens and parameters; the measured delay and overhead are recorded explicitly. All **1,126 Python tests**, five concurrent browser checks and eight existing-app checks pass. This is not distributed gradient training or a sustained production-load benchmark.

The [TRL runtime audit](../research/trl-runtime-2026-10-11/README.md) adds actual six-step optimizer execution and evaluation with a tiny local random model, exact baseline/capture comparison, batch-atomic local enqueue, explicit scorer/capture failure handling, and all 16 raw reward receipts checked through the actual server. A fresh-directory repeat passes. Seven browser checks cover train/evaluation curves and source review; four existing saved-history checks still pass. All **1,115 Python tests** pass. This uses local model generation and zero external/paid inference calls. Single-process CPU correctness does not establish GPU/distributed throughput or behavior-label accuracy. See [the practical capture contract](TRL_CAPTURE.md).

The [11 October native/batch audit](../research/native-adapters-2026-10-11/README.md) adds hash-pinned published τ-bench replay, native participant/visibility edge cases, complete-file atomicity, UI/CLI JSONL identity, a 37 MB CLI check and eight browser checks. All 1,105 Python tests passed. It uses an isolated database and zero model calls. Published evaluation traces have no training coordinates; this replay does not establish training-time generalization.

The [audit bundle](../research/portability-2026-10-09/README.md) distinguishes authored controls, pinned public replay and real environment execution. It includes 121 focused tests, eight browser workflow checks, an isolated wheel installation check and actual Gymnasium execution. Capture and source metrics used no model tokens. The two Gym episodes are controlled examples, not training curves from a learned policy.

Still unproven or absent: GPU/distributed trainer end-to-end integrations, large-job throughput, arbitrary Responses/OTLP imports, image/audio semantic inspection, universal multi-agent adapters, delta ingestion, object storage and a hosted multi-tenant service. The collector remains loopback-only. Requests are limited to 20 MiB, pending outbox defaults to 256 MiB, and whole snapshots grow with trajectory length; cadence and recorded sampling matter. Semantic accuracy cannot be inferred from adapter tests.

The next acceptance gate for any native trainer plugin is a pinned small run showing: counted producer rollouts equal captured rollouts under the declared sampling policy; crashes/lost acknowledgments recover without duplication; clocks and generating policy identities match producer logs; full/native records and normalized events agree; overhead and queue age remain bounded; then a domain-specific held-out semantic review. Hook research alone does not satisfy this gate.
