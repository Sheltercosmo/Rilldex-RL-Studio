# Product workflow improvements

Progress against [the competitive review](COMPETITIVE_PRODUCT_REVIEW_2026_10_21.md).

Implemented:

- First session: example, file import, or live connection. The example contains inspectable source records and a retry timeline; it is explicitly synthetic.
- Installed candidate adapter, local/API presets, offline configuration check and explicit one-request contract probe.
- Experimental work-content extraction directly from saved graphs: staged generation, bounded contract repair, per-feature selection, provider usage and cached resume. Public-source trials retain observed semantic errors; this does not replace the main map extractor. [Evidence and use](SCOPE_MEMBERSHIP.md).
- New content extraction separates operations and stated purposes without splitting base units. Feature generation supplies expressions without duplicate scope judgments. Resume retains the original protocol; optional local syntax supports token addressing and attachment review.
- Work-content extraction now saves each stage and attachment decision to the workspace. The existing unit inspector refreshes these records; native SQL and portable research exports expose the same contents, pending decisions and source references. Cached resumes retain visible progress.
- Optional local relationship inspection connects extracted work with purpose, order, condition and response-to links. Candidates are constructed in code and inspected in bounded Jev pages; the unit panel and native analysis retain pending decisions. [Trial and remaining inference errors](SCOPE_MEMBERSHIP.md).
- Cross-domain work extraction now separates conditions and removes duplicate summary/detail items. Revised relationship questions reduce goal/feedback confusion; saved protocols resume unchanged. [Public-source trial, regressions and remaining ordering error](../research/cross-domain-work-2026-10-21/README.md).
- Single-rollout pilot in the UI or Python CLI, with lifetime budgets, separate provider usage, resumable work and a completed-map link.
- New pilots continue from activities into paged work-target comparisons within the same allowance. Long traces retain inspected/pending pairs, session boundaries and unordered dispatches. Local maps remain available during resume. [Validation](../research/paged-work-links-2026-10-21/README.md).
- Plan-to-action comparisons now run in the same pilot, with multiple supported stages, resumable pages and direct Plans & attempts navigation. A public development trial exposed an overbroad preparation link that remains recorded. [Evidence](../research/plan-links-2026-10-21/README.md).
- The pilot now inspects executor errors and warnings, enabling existing return-after-error paths and behavior measures. Older pilots can add this inspection without rebuilding annotations; response progress shares the lifetime budget. [Use](MODEL_SETUP.md).
- Continuous observation now carries the same plan, work-link and feedback stages across an experiment. The installed `models watch` command reuses a pilot, follows arriving rollouts and adds saved behavior measures to the dashboard. [Use](CONTINUOUS_OBSERVATION.md), [validation](../research/continuous-behavior-2026-10-21/README.md).
- New plan comparisons distinguish upstream work from direct step roles. The live development trial corrected the retained false preparation link while preserving edits and compound roles; saved pilots keep their protocol. [Results and limits](../research/plan-boundaries-2026-10-21/README.md).
- Workers now restart with saved settings without repeating the pilot argument. Offline package refresh replays saved evidence before retaining an observer; usage, blocked jobs and published maps are preserved. The setup form separates Start, Resume and Refresh and omits unchanged limits. [Use](MODEL_SETUP.md), [validation](../research/worker-refresh-2026-10-21/README.md).
- Repeated-attempt comparisons now feed behavior charts and the Python API. Monitor presets and continuous observation expose input changes, matching feedback and unknown comparisons; each case opens both attempts, differences and intervening work. [Use and validation](WORK_STRUCTURE_MEASURES.md#compare-repeated-attempts).
- Behavior distributions now compare revisit patterns across rollout windows. Exclusive categories retain unknowns; each case opens its saved attempt pair and returns to the same chart selection. No model calls are needed. [Validation](../research/revisit-distributions-2026-10-21/README.md).
- Work-path review uses those same comparisons, including native arguments and ordered feedback. Source-only responses and split annotations remain visible without duplicate results; pair inspection returns to the selected work path. [Validation](../research/work-review-native-2026-10-21/README.md).
- New pilots and workers run approach comparisons automatically. Work path and distribution cases retain the selected stated reason, before/after responses, source links, search and export. Older pilots can add the pass without regenerating units. [Use](MODEL_SETUP.md), [validation](../research/approach-pilot-2026-10-21/README.md).
- Saved executor inspections now accompany approach comparisons. **Errors on repeated work** tracks the next same-work response, with exact evidence, unknown inspections and source-bound navigation. Continuous workers add the measure automatically. [Use](WORK_STRUCTURE_MEASURES.md).
- Work review filters errors reported on both attempts; the timeline shows response badges beside procedure changes. Counts retain missing inspections and open the exact pair. Desktop/mobile installed replay covers software and airline traces without new model calls.
- Import receipts show available analysis and missing inputs. Source maps link directly to model setup with the rollout selected.
- Readiness uses saved source, graph and trainer records. Monitor definitions are distinguished from monitors producing measurements.
- Directory connections can assign a stable producer identity; explicit identities still work.
- Map presets follow recorded failed checks, retries and paired attempts. Unit/edge navigation retains the selected path; exiting restores the full map. Recorded checks can be loaded without inference.
- Saved interval investigations compare task-matched rollout cases, with outcome filters, explicit trial selection, frozen graph versions and source-map links. Missing context and unmatched cases remain visible.
- Training signals and Investigations now open two-run case comparisons. Each side can select all captured rollouts, a checkpoint or an explicit rollout-clock range. The same capture is available through `Workspace.compare_rollouts`; saved comparisons support evidence navigation, follow-up findings and report export.
- Case comparisons expose failed-check and retry paths directly. Paths follow later explicit retry/recheck links with exact source navigation; ambiguous split-action check attachments no longer draw an arbitrary recheck arrow. [Usage and validation](BEHAVIOR_MAP_INTERFACE.md#follow-and-compare-attempts).
- Plan-attempt measures retain original graph relationships. Split annotations of one captured call count once across maps, branch effort, retries and decision windows; individual evidence remains inspectable. [Counting rules](WORK_STRUCTURE_MEASURES.md).
- Plan cards, attempt paths and legacy stage measures now share dispatch-level counts. Offline refresh preserves old receipts and the rollout population; session boundaries, unknown order and conflicting product readings remain explicit. [Validation](../research/plan-counts-2026-10-21/README.md).
- Weave JSON/JSONL exports group calls into trace snapshots, preserving native nesting, source links and available W&B context. Recorded model outputs are decoded; copied input histories and marked scorer calls stay separate. Updated exports retain history without duplicating the rollout population.
- Full-run telemetry uses an incremental scalar index, extrema-preserving plots, complete interval statistics and EMA. Researchers can search all captured metrics, page through original updates and export replayable JSONL. Selected captures remain fixed across late arrivals and reloads until resumed.
- Detector validation freezes reviewed labels into named sets with task-grouped development/held-out splits. Saved monitor versions and explicit Python evaluations share coverage reports, comparison filters and exact case evidence. Diagnostic indicators now use the existing full-source review workflow.
- Saved investigations provide a readable findings report and offline HTML export. Researcher conclusions, counterevidence, pending checks, cohort counts, measurement coverage and explicit source excerpts retain the same saved revision. Python export uses the same renderer.
- Public ms-swift GRPO logs now have native reward-component and entropy definitions. Default charts choose total reward, mean completion entropy and regional policy clipping; ancillary fractions and extremes remain selectable.

Validation uses an actual local HTTP candidate endpoint and deterministic decision responses, including installed-wheel execution outside the checkout, budget exhaustion, resume, publication and cache reuse. Browser checks cover desktop/mobile onboarding, import, model setup, inspection paths and case comparison/navigation. Tests retain frozen comparisons after late arrivals and annotation changes. These checks do not measure model accuracy or validate every provider/OS.

Full-run telemetry was exercised with 50,001 synthetic native records and 106 metric series, including early/late anomalies, late conflicting logs, frozen reloads and exact exports. Local Windows timings: about 7.5 seconds to index and query initially, 2.1 seconds for a subsequent query. This is a bounded test, not a production-scale benchmark.

Detector validation passed 59 targeted Python checks, 365 existing frontend checks, desktop/mobile navigation and installed-wheel execution outside the checkout. Ten authored cases exercise improvements, regressions, missing results and worker errors. No model calls were used; these controls validate the workflow, not real-world detector accuracy. [Use validation sets →](DETECTOR_VALIDATION_SETS.md)

Findings reports passed 88 targeted backend checks, existing frontend checks, desktop/mobile export and offline browser viewing with no network requests. Installed-wheel Python export also passed outside the checkout. Tests retain original findings after later revisions and late arrivals, preserve missing measurements, and include reward comparisons and quoted evidence. [Share a report →](FINDINGS_REPORTS.md)

An installed-wheel replay reconciled all six Plan attempts in the retained public software graph with their original relationships; saved monitor evidence survived database reopen and repeat sync. No model calls were used. These checks validate counting and evidence integrity, not independent semantic accuracy.

Validation covers independent clocks, missing coordinates, frozen late-arrival behavior, task matching, map/back/reload, Python capture and report export. The comparison controls are authored, not real training-effect estimates; no model calls were used.
