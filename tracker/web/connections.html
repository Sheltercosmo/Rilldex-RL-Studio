Capture from any Python rollout loop
Send a conversation, environment episode, generation or supported native record. Delivery uses the same readers as file import. Give every worker a stable producer identity and its own persistent outbox.
from rilldex import Outbox, chat_document

capture = Outbox(
    "worker-0.sqlite", producer="run-a/worker-0",
    endpoint="http://127.0.0.1:8765",
).start()

# Call from your rollout loop with its actual history and stable rollout ID.
def record_rollout(rollout_id, messages, *, finished=False, reward=None):
    capture.log(
        rollout_id=rollout_id,
        document=chat_document(messages, reward=reward),
        state="complete" if finished else "in_progress",
        metadata={"experiment": "run-a"},
    )

# record_rollout("sample-42/repeat-0", messages, finished=True, reward=1)
# On shutdown: capture.close(). Pending deliveries remain on disk.


Use a collector endpoint reachable from the worker (forward its port for remote jobs). Publish after an agent step or at completion. Keep the same rollout ID to create revisions. Supply full snapshots, not token chunks. Add recorded generation step, learner step, policy version and sample identity when available; capture time is not training progress.


Environment loop · actions, observations and model output
from rilldex import Episode

# environment is your Gymnasium-compatible environment.
observation, info = environment.reset()
episode = Episode(episode_id="episode-42", goal="Reach the goal.").reset(observation, info)

# After each environment step:
episode.gym_step(action, environment.step(action))
capture.log("episode-42", document=episode.snapshot(), state="in_progress")
# Send state="complete" at the end. Terminated and truncated stay distinct.
For custom environments, use Episode.step with explicit action and observation. Episode.openenv_step accepts OpenEnv-style output. Use JSON-safe state projections and references for large media; images and audio are retained as references, not visually analyzed. Include recorded model output with model_response when available to enable semantic inspection of the agent alongside environment transitions.


Single-turn reasoning or generation · prompt and completion
from rilldex import generation_document

capture.log(
    "sample-42/repeat-0",
    document=generation_document(prompt, completion, reward=reward),
    state="complete",
    metadata={"experiment": "run-a"},
)
Recorded text and explicit outcome are sufficient. A flat completion cannot establish executed tool calls or intermediate environment states. Those measures stay unavailable instead of being inferred from text.


Recover pending delivery or use a remote training host
python -m rilldex outbox worker-0.sqlite --producer run-a/worker-0
python -m rilldex outbox worker-0.sqlite --producer run-a/worker-0 --send
Run the tracker beside the job and forward its loopback port with SSH, or mount/sync the output directory. The tracker remains bound to localhost. A directory collector can only observe what the framework has written; it cannot stream unsaved agent steps.
Blocked delivery is visible in outbox status. Correct producer/schema conflicts before resuming; pending snapshots are never silently discarded. A fresh outbox needs a new producer namespace.

Record while training
Send the trainer's existing reduced logger dictionary; no extra model computation is required.
from rilldex import Outbox, TrainerTelemetry

outbox = Outbox("trainer-outbox.sqlite", producer="run-a/learner",
    endpoint="http://127.0.0.1:8765")
outbox.start()
metrics = TrainerTelemetry(outbox, experiment="run-a", framework="verl",
    framework_version="your-installed-version", objective="gspo/config-v1",
    session="training-start-1")
metrics.log(native_metrics, step=global_steps)
For TRL, choose trl-grpo or trl-ppo; for ms-swift GRPO, choose ms-swift-grpo. Attach trainer.add_callback(metrics.transformers_callback()). Other loggers use custom with explicit metric definitions. Keep a stable session on resume; change it when counters restart.
Stable-Baselines3 · native metrics and vector episodes
from rilldex import Run
from stable_baselines3 import PPO
from stable_baselines3.common.env_util import make_vec_env

with Run("cartpole", project="control", workspace="study.sqlite") as run:
    capture = run.stable_baselines()
    env = capture.wrap_env(make_vec_env("CartPole-v1", n_envs=4))
    try:
        model = PPO("MlpPolicy", env)
        model.learn(4096, callback=capture.callback())
    finally:
        env.close()
Select the run in Overview for Training signals, Run details and captured Rollouts. Omit wrap_env for metrics only. Existing logger outputs remain attached. For remote/offline capture, pass target=outbox to Run. Native CPU coverage: SB3 2.9.0 PPO/DQN, vector environments and restarts.

Execution & signals
Connect sampler activity, learner updates and weight synchronization to their recorded metrics and rollouts. The overview lets you select one time interval and save its evidence.
from rilldex import ExecutionRecorder

execution = ExecutionRecorder(outbox, experiment="run-a", clock="run-a/utc")
with execution.span("update-42", kind="learner_update",
        context={"worker": "learner"},
        configuration={"precision": "nvfp4"}) as span:
    # Run your update and capture its native log.
    metrics.log(native_metrics, step=42, record_id="log-42", training_uses=use_refs)
    span["telemetry"] = [{"producer": outbox.producer, "id": "log-42"}]
Use actual shared clock coordinates; separate unsynchronized hosts. Inference spans also carry their rollout producer, ID and source revision. Logs link to exact training-use receipts rather than matching step numbers.
