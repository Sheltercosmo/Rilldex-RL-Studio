Ubuntu, Windows or macOS · separate collector environment

Use Python 3.11+ independently of your trainer. No GPU, Node or model key is needed. From this checkout:

python -m venv .venv
# Ubuntu / macOS
.venv/bin/python -m pip install .
.venv/bin/rilldex --db ./workspace/tracker.sqlite start --open
# Windows PowerShell
.venv\Scripts\python.exe -m pip install .
.venv\Scripts\rilldex.exe --db ./workspace/tracker.sqlite start --open

On Ubuntu use python3 if needed and install python3-venv if venv is missing. Offline machines can install the built wheel with pip --no-index --no-deps. This development package is not assumed to be on PyPI. Pin the database path so a different working directory does not create a new workspace.

Docker · persistent volume, read-only job output

Create outputs/ beside compose.yaml, or set RILLDEX_OUTPUT_DIR to an existing absolute output directory in a .env file. Set RILLDEX_INPUT_MODE to exports (JSONL), native (Harbor/SWE-agent) or snapshots (one JSON per rollout). Keep RILLDEX_PRODUCER and RILLDEX_EXPERIMENT stable.

docker compose up --build -d --wait
# Open http://127.0.0.1:8765

docker compose stop
docker compose start

The non-root container keeps the workspace in jev-data and reads /outputs. Existing files are collected, then new files and appended rows. Stop/start and container recreation retain that volume; do not use down --volumes for a normal stop. RILLDEX_PORT changes both the internal and localhost-published port. The base image does not include cloud SDKs.

Remote Ubuntu / GPU host · inspect over SSH

Run the collector beside accessible output in a persistent CPU session or service, independently of training:

rilldex --db /local-disk/jev/workspace.sqlite start --watch /jobs/run-a/outputs --mode exports --experiment run-a --producer run-a/exports
# On your workstation, use the same port on both ends:
ssh -N -L 8765:127.0.0.1:8765 training-host

Open localhost:8765 on your workstation. Closing the tunnel does not stop a separately running collector. A sample systemd user service is in deploy/rilldex.service; replace its absolute paths. Keep SQLite on local persistent disk, not NFS or object mounts. Cluster scheduling and file permissions are site-specific.

S3 or Google Cloud Storage · existing objects and future output

Install the storage extra in the collector, then use the cloud prefix directly in Watch a job or the CLI:

python -m pip install '.[s3]'
rilldex --db ./workspace/tracker.sqlite start --watch s3://bucket/run-a/outputs --mode exports --experiment run-a --producer run-a/cloud
# GCS: install '.[gcs]' and use gs://bucket/run-a/outputs
# Check without importing: rilldex watch PREFIX ... --check
# Drain completed output: rilldex watch PREFIX ... --once

Use the host's SDK credentials/profile/workload identity. Never put keys or signed URLs in this form. The source is read-only. Changed objects are cached beside the database before normal ingestion; interrupted downloads retain the previous copy. Restart resumes the cache and cursors. A cloud outage shows Using cached output: already downloaded records continue, while new remote output is unknown. The last complete cloud sync is separate from receipt time. One-off replay exits unsuccessfully until cloud access returns. Deleting an object does not erase saved evidence.

For S3-compatible storage, set the standard endpoint before starting the collector; keep credentials in its SDK environment/profile:

# Ubuntu / macOS
export FSSPEC_S3_ENDPOINT_URL=https://your-object-storage.example
# Windows PowerShell
$env:FSSPEC_S3_ENDPOINT_URL='https://your-object-storage.example'

The source remains s3://bucket/prefix. This route was checked with the real s3fs client and a local Moto HTTP service using authored data. Real account permissions and production endpoints still need validation. Run the collector separately from training that forks worker processes; s3fs requires spawn or forkserver when sharing a process.

Preview downloads at most five objects and 32 MiB into temporary storage. Collection accepts objects up to 1 GiB, at most 100 changed objects per pass. Prefer narrow prefixes and bounded immutable shards: this polls storage and can re-download growing objects. Overwritten intermediate snapshots cannot be recovered. Azure or other cloud CLIs can mirror to a local watched directory; native Azure integration is not included.

Colab / notebooks · capture without a persistent web server

Install the wheel in the runtime and keep the active database on runtime-local disk. Rerunning the setup cell reuses the session; no public tunnel or model call is required.

from pathlib import Path
from tracker.notebook import open_workspace
Path('/content/outputs').mkdir(parents=True, exist_ok=True)
inspection = open_workspace('/content/rilldex/workspace.sqlite')
inspection.watch('/content/outputs', producer='run-a/exports',
                 experiment='run-a', mode='exports')
inspection.start()
inspection.status()
inspection.rollouts(10)

inspection.stop()  # returns stopped or stopping
inspection.status()['state']  # wait for stopped before starting again
inspection.snapshot('/content/inspection-001.rilldex.zip')
from google.colab import files
files.download('/content/inspection-001.rilldex.zip')

Save the archive and source outputs outside the runtime before it is deleted. Copy a finished archive to Drive, not a live SQLite database. Restore the archive locally to use the full map and investigation UI. Restored connections are paused; change the output location and resume. The helper cannot recover unsaved runtime data or keep Colab alive. A hosted notebook web UI is not implemented.

# In this project, or install its wheel in a separate collector environment:
python -m pip install .
rilldex start --open

Use Watch a job for an empty directory, a running job or completed output. Native collection reads Harbor / SWE-agent files and late results. JSONL collection replays existing records, then follows appended rows from any supported single-rollout adapter.

rilldex start --watch ./outputs --mode exports --experiment run-a --producer run-a/worker-0

# Replay a completed export directory without starting a server:
rilldex watch ./outputs --mode exports --experiment run-a --producer run-a/worker-0 --once

# Check local installation and storage; select a free port:
rilldex doctor --port 0
rilldex start --port 0

Keep the same database, producer, experiment and relative filenames when resuming. Every JSONL row must end with a newline. Raw records mean a complete exported rollout; use explicit revision envelopes for ongoing work. An accepted row cannot be rewritten. Import files is for frozen artifacts, not repeated uploads of a growing file.

The default database is .tracker/tracker.sqlite under the working directory; pin it with rilldex --db /local-disk/tracker.sqlite start. Windows, Linux and macOS use the same CLI. Keep SQLite on local disk. On a training host, omit --open and forward the port with ssh -L 8765:127.0.0.1:8765 training-host. Public multi-tenant deployment is not implemented.

Check a directory, then follow it

For portable conversations, episodes or generations, choose JSON — one file per rollout in Connections. Updating the same relative filename creates a revision. Use the Harbor / SWE-agent route when native sidecars and continuations matter.

rilldex watch ./outputs --mode snapshots --experiment run-a --producer run-a/worker-0 --check
rilldex start --watch ./outputs --mode snapshots --experiment run-a --producer run-a/worker-0

The check decodes up to five files and reports usable evidence, missing training coordinates and invalid or incomplete input. It makes no model calls and imports no records. For completed output, use the same rilldex watch command with --once --snapshot-state complete. Keep the same database, producer and relative filenames to resume without duplicates.

Raw JSON defaults to work in progress. Explicit envelopes supply their own identity, revision and state. Polling sees saved snapshots; use the outbox or append-only JSONL when every intermediate revision must survive. Prefer atomic file replacement when writing snapshots. Frozen file import uses separate artifact identities.

Move the inspection workspace

Use Connections → Import files → Move or back up this workspace to download a portable snapshot while collection continues. The CLI supports the same export and a verified restore into a new database:

rilldex --db ./current.sqlite workspace snapshot experiment.rilldex.zip
rilldex workspace inspect experiment.rilldex.zip
rilldex --db ./restored.sqlite workspace restore experiment.rilldex.zip
rilldex --db ./restored.sqlite start --open

Restoration refuses to overwrite an existing file. Sources, graphs, measurements, investigations and review notes retain their identities. Available observer results are frozen with their audit receipts, so inspecting them does not require the original absolute paths. Read the manifest for unavailable observer results. This preserves an earlier structural audit; it does not rerun or independently validate it.

Collection and pending inference are paused in the copy. Reconnect the intended output directories before resuming. External worker outboxes, training data and original candidate-generation/audit workspace files are not included; keep those when continuing extraction development. The archive contains your recorded source data and is saved locally.

2. Identify the rollout and the clock

from tracker.capture import Outbox

tracker = Outbox("worker-0.sqlite", producer="experiment-a/worker-0").start()
metadata = {
    "experiment": "experiment-a", "task_id": task_id,
    "sample_id": sample_id, "rollout_n": repeat, "split": "train",
    "training_step": generation_iteration,
    "training_step_basis": "generation_iteration",
    "generation_step": generation_iteration, "learner_step": learner_iteration,
    "policy_version": generating_policy_version,
    "environment": environment_name, "environment_version": environment_version,
    "sampling": "all rollout completions", "training_inclusion": "pending",
    "reward_definition": "my-reward-v1"
}

These variables must come from your producer. Omit unknown fields. Do not reuse the learner step as the generating policy identity in asynchronous training. Preserve per-call policy versions in native trajectory records when a rollout spans a weight change.

One outbox belongs to one producer/worker. Keep its file across restarts. Keep the same rollout ID across snapshots and distinct IDs for repeats; do not substitute a prompt hash for a repeated sample's identity.

3A. Chat and tool workflows

from tracker.portable import chat_document

document = chat_document(
    messages=agent_visible_messages, tools=tool_definitions,
    metadata=metadata, reward=explicit_final_reward,
)
tracker.log(rollout_id, document, state="complete")

Supply recorded system/developer/user/assistant/tool messages. Calls and results bind by native IDs, including parallel calls. Missing IDs stay unlinked. Invalid generated argument strings remain observable attempts. Do not concatenate private user-simulator tools or independent subagent histories into the assistant's context.

ART exposes a materialized message history; TRL, slime, OpenRLHF and AReaL expose rollout/agent hooks. Those are candidate bridge locations, not adapters tested inside each trainer. Check the framework evidence matrix before choosing one.

3B. Environment steps

from tracker.portable import Episode

episode = Episode(metadata=metadata, goal=explicit_agent_task,
                  episode_id=rollout_id)
observation, info = env.reset()
episode.reset(observation, info)
while True:
    # Use your existing policy and action parser; capture does not call a model.
    model_response = policy_response(observation)
    saved_response = str(model_response)  # Preserve before a mutating parser.
    action = parse_action(model_response)
    result = env.step(action)  # Gymnasium's five-value result
    episode.gym_step(action, result, model_response=saved_response)
    observation, reward, terminated, truncated, info = result
    done = terminated or truncated
    # For long trajectories, batch intermediate snapshots to a chosen cadence.
    tracker.log(rollout_id, episode.snapshot(),
                state="complete" if done else "in_progress")
    if done:
        break

Supplying episode_id enables version 2: each turn preserves model text, the dispatched action and returned observation as separate linked records. Optional turn_id and response_id retain native identity; otherwise turn IDs use the captured episode sequence. Omit model_response when unavailable. Turns with model text reports coverage; it does not measure semantic accuracy. Capture text before a parser changes it in place. One response dispatching several actions needs the conversation/batch contract, not duplicated text across turns.

NumPy scalars are converted. Project state arrays explicitly with tolist(); store screenshots/audio as typed media references. Episode(..., visible_context=...) can preserve action meanings and observation instructions that the agent actually received. Never put hidden evaluator state there.

OpenEnv has a different contract: use episode.openenv_step(action, observation_object). Its native done does not say whether termination or truncation occurred. Environment info, step reward and ending flags remain separate from agent-visible observations. Additional histories and multi-agent state require their own trajectories.

3E. TRL GRPO reward callback

import trl
from tracker.trl_capture import GRPOCapture

# `tracker` is the started Outbox above, unique to this worker/component.
capture = GRPOCapture(
    tracker, experiment="experiment-a",
    reward_definition="my-reward-component/v1",
    trainer_version=trl.__version__, on_error="warn",
    context=lambda: {
        "split": "train" if trainer.model.training else "evaluation",
        "worker_rank": trainer.accelerator.process_index,
        # Supply actual sampler policy identity if known.
    },
)
trainer = trl.GRPOTrainer(
    model=model, args=training_args, processing_class=tokenizer,
    train_dataset=dataset,
    reward_funcs=capture.wrap_reward(my_reward_function),
)
trainer.train()
print(capture.status())

Put tracking_task_id and tracking_sample_id into dataset columns when available. Repeated completions remain distinct. This callback records one reward component and the trainer global-step counter at scoring time; a generation batch reused for multiple optimizer steps is captured once. It does not prove which samples entered the loss. Train and evaluation curves stay separate.

Explicitly choose on_error="warn" to continue the reward function with a warning and missing capture, or "raise" to stop on capture failure. A reward exception is retained as a failed scoring source when possible and then re-raised. Every callback batch commits atomically to the local queue; HTTP delivery remains per rollout. Use separate queues for workers and separately captured reward components.

Verified: actual TRL 1.13.0 CPU training/evaluation, 16 completions, identical capture-on/off model results, lost-acknowledgment recovery and source-linked charts. TRL 1.15.0 failed on this Windows CPU in its required Triton path. GPU, distributed workers, vLLM and live tools need separate validation. Capture occurs after generation; use an execution hook for intermediate steps or tool identities missing from reward inputs.

Validated: TRL 1.13.0, Transformers 5.19.0, Accelerate 1.15.0, Torch 2.14.1; single-process FP32 CPU, native AdamW and plain-text prompts. Open Training health, choose the experiment and leave View → Automatic. Prediction error, target, reward and cached baseline link to exact samples. Backward completion and optimizer completion are separate record streams. The displayed per-use MSE is not automatically the scaled total trainer loss. Reference completions are retained separately without invented training membership.

The strict opt-in hook stops on capture errors and invokes no extra model or reward calls. Native capture-on/off CPU controls produced identical model updates. See docs/TRL_A2PO_CAPTURE.md and research/a2po-native-2026-10-12/README.md in the workspace for the full audit and limits.

5. Follow each worker's delivery

tracker = Outbox(
    "worker-0.sqlite", producer="experiment-a/worker-0"
).start(report_status=True, report_interval=5)

print(tracker.status())  # includes delivery_report_error, if reporting failed

Worker delivery shows the last reported pending/blocked snapshot counts, queue capacity and oldest queued age alongside collector-confirmed revisions and rollouts. Reports contain counters and queue identity, not source text, local paths or raw error messages. They do not establish capture completeness or model/training health.

Reporting runs independently of delivery. A slow ingestion request does not prevent a queue report. A report becomes overdue after the larger of 15 seconds or three report intervals. No report means unknown queue state; an overdue report is not proof of a dead worker. Graceful close attempts a final sender-stopped report. An offline shutdown may leave the last report overdue instead.

Keep the same outbox file across restarts: its identity and monotonically increasing report sequence survive. Delayed or duplicated reports cannot refresh stale status, and replacing a queue under an existing producer is rejected. Reporting is opt-in and requires an updated collector; a report failure is recorded locally and never blocks source delivery. Reading an outbox with the CLI does not send a report.

6. Delivery and operating limits

print(tracker.status())  # pending, blocked, oldest pending age, errors
tracker.close()          # stops delivery; does not discard or flush pending data

# Resume delivery after a restart:
python -m rilldex outbox worker-0.sqlite --producer experiment-a/worker-0 --send

Local logging serializes and commits to disk; it is not zero overhead. HTTP delivery retries exact revisions. Each request is limited to 20 MiB and pending storage defaults to 256 MiB; full queues raise an error. Catch that error in your integration, retain the native record, and record any deliberately reduced sampling. Full snapshots grow with trajectory length: use bounded sampling/cadence and inspect queue age. S3/GCS files can use the cloud collection route above. Delta ingestion, distributed throughput validation, OTLP and automatic Responses-event translation are not implemented.

Capture and source metrics require no model tokens. Semantic analysis cost is separate. This release has a real Gymnasium runtime audit and contract tests, not a distributed RL throughput benchmark.

7. Bound semantic inspection work

Source capture and source metrics do not require inference. Coherent semantic units need proposed boundaries, activities and readable contents before Jev selects among them. A general candidate generator is not bundled: supply candidate files or configure a JSON candidate command. Dashboard reads do not run this workflow.

For long-running rollouts, add --live-prefixes when creating a semantic watch-init worker. It observes received snapshots before completion, reuses exact earlier requests and preserves lifetime spending limits. Streaming rows link the behavior map only when it covers the current snapshot. Unfinished rollouts stay out of completed-rollout monitor values. A failed earlier prefix still requires an explicit retry when the source grows. See docs/SEMANTIC_WORKSPACES.md for the command contract and operating limits.

# Freeze one imported rollout and queue initial requests (no inference):
python -m rilldex semantic prepare inspection --run-id YOUR_RUN_ID

# Inspect queue, coverage and any recorded usage:
python -m rilldex semantic status inspection

# Resume supplied candidates with an explicit per-execution allowance:
python -m rilldex semantic run inspection --prompt-key --max-new-calls 20 --max-candidate-calls 0 --max-input-bytes 500000

# Validate source bindings and saved selections without inference:
python -m rilldex semantic audit inspection

Defaults allow up to 50 new Jev request invocations, 50 candidate process invocations and 1,000,000 combined UTF-8 request bytes per execution. Resume starts a new allowance; cached work does not consume it. Set all three limits to zero for cache-only execution. Limits do not change Jev's maximum-probability selection.

A budget stop saves the current incomplete pass and preserves the last completed map. Status reports eligible, visited and unvisited source windows, selected source-byte coverage, stage attempts and provider-reported token usage. Coverage measures annotation progress, not semantic accuracy. Calls without token reports remain unknown. Limits count request invocations and payload bytes, not billed tokens or money: Jev may retry internally, and a candidate command may make several model calls. Keep its own provider-side limits and metering.

Collect and compare inspection coverage alongside behavior rates. Inspecting only failures or short rollouts changes the sample population; those rates cannot be presented as whole-training prevalence. Keep sampling choices explicit and compare compatible observer protocols.

8. Connect checks to the state they tested

Use WorkStateRecorder beside the tool loop to connect actual input versions, edits, check results and deliveries to source events. It enriches an existing trajectory for the same outbox/import route. This supplies the state graph behind recorded-criterion recovery and verification-at-delivery monitors.

from tracker.state_capture import WorkStateRecorder, source_ref, file_versions

state = WorkStateRecorder(environment=actual_environment_version)
action = source_ref("/trajectory/0/action")
result = source_ref("/trajectory/0/observation")
snapshot = state.snapshot(action, file_versions(workspace, input_paths))
state.check(action, result, snapshot=snapshot,
    criterion_id="acceptance", criterion_version=actual_criterion_version,
    required_objects=input_paths, outcome=recorded_outcome,
    state_stable=None)

enriched = state.attach(native_trajectory, format="swe-agent")
outbox.log(rollout_id, enriched, format="swe-agent", state="complete")

Record the inputs at dispatch and the outcome after the actual result arrives. Supply the criterion and dependency scope explicitly. state_stable=True requires producer evidence that the scoped inputs stayed fixed, such as execution over captured immutable inputs. Equal before/after hashes alone are insufficient. Unknown stability leaves recovery and final applicability unknown.

Use state.edit(..., before=..., after=...) for actual state changes and state.deliver(..., snapshot=..., requirements=[...]) for explicit delivery requirements. JSON business/browser objects can use object_version(value). The recorder resolves source pointers or exact call IDs, rejects missing or ambiguous bindings, and never rewrites source messages or overwrites existing state evidence. File hashes do not retain file contents.

In Monitors, add an analysis measure for checks bound to state, recovery of the recorded criterion, or verification applicable at delivery. These describe recorded work and evidence, not inferred strategy or whole-task success. The executed audit covers eight controlled software/business cases across SWE-agent, Harbor/ATIF and chat encodings; it is not a live agent-framework evaluation.

9. Connect mini-SWE-agent v2

Use the public save hook in the producer environment. This integration was executed with upstream 2.4.6 using its default agent, local environment and deterministic models. Text, tool-call and Responses API records retain parsed actions, actual outputs and interruption reasons.

from minisweagent.agents.default import DefaultAgent
from tracker.capture import Outbox
from tracker.mini_capture import CaptureMixin, MiniCapture

class ObservedAgent(CaptureMixin, DefaultAgent):
    pass

outbox = Outbox("worker-0.sqlite", producer="run-a/worker-0").start(report_status=True)
capture = MiniCapture(outbox, rollout_id=actual_rollout_id,
    context=lambda: actual_rollout_metadata, on_error="warn")
agent = ObservedAgent(model, environment, capture=capture, **agent_config)
try:
    result = agent.run(task)
finally:
    print(capture.counts, capture.last_error, outbox.status())
    outbox.close()

The original native file is saved first. Logging queues a full snapshot locally; the background worker delivers it. warn preserves execution and reports capture failures; choose raise to stop on capture failure. Closing does not guarantee delivery: preserve the outbox and replay pending revisions. Use a new rollout identity for every new run.

A recorded step limit or repeated format-error stop is a complete trace, not task success. Unexpected exception exits remain failed/partial. No training step is inferred from model-call counts. To add state-aware measures, supply enrich=lambda doc: state.attach(doc, format="mini-swe-agent") using versions captured in the actual environment hook. Capture uses no model tokens; semantic processing is separate. Full snapshots grow with trajectory length: watch backlog and storage. The native audit uses authored outputs and does not validate policy quality, containers or distributed training.

Measure revision benefits and regressions

Open Behavior → Self-revision and add the preset using your saved observation source. Open a value for the change, first follow-up and source evidence. Configure thresholds in Monitors.

For criterion comparisons, use the existing state recorder: capture a baseline check, state.edit(..., before=..., after=...), then recheck with the same criterion/version, environment and required objects. Record input stability. The edit must link to the revision’s implementing action. Both improved and regressed checks appear; a later pass does not replace the first recheck.

Executor completion is measured separately from criterion results. Missing state or changed check definitions remain unresolved. Existing saved graphs retain their original capture.

Join behavior to training samples

The Training samples view compares existing behavior monitors across explicitly recorded populations. Sample declarations, scores, filter decisions and individual training uses arrive independently. A reward callback alone does not prove optimizer use.
